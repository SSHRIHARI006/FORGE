# ADR-001: Filesystem Convention Over Database/Runtime for V1

## Decision

Implement Forge V1 as a markdown filesystem convention (`.forge/` + `FORGE_SPEC.md`) with no daemon, database, hosted service, agent runtime, orchestration server, or dashboard.

## Context

SPEC §§2, 25, 30 require V1 to be a portable, agent-agnostic context layer. Genesis-inspired ideas (discovery, spec-first, ADRs, tasks, verification evidence, checkpoints, kickoff) are wanted without Genesis's runtime machinery. This repo was fresh (only `SPEC.md`), so there was no existing infra to integrate with.

## Alternatives

- Lightweight SQLite/workflow DB for tasks/state with file export.
- Daemon or MCP/orchestration server managing context and handoff.
- Full Genesis-style state machine + event DB + dashboard.

## Reason

- Portability: plain files are readable by any agent and human without tooling; no lock-in.
- Simplicity (SPEC §3.6): no infra to deploy, secure, or migrate; versioned naturally with git.
- Agent-agnostic: avoids coupling to one agent's memory format or runtime.
- Sufficiency: V1 success (second agent continues without conversation) is achievable with disciplined markdown + git.

## Status

Accepted
