# ADR-003: Agent-Agnostic Markdown as Canonical Format

## Decision

All persistent project knowledge uses plain Markdown under `.forge/` + `FORGE_SPEC.md` with stable IDs (`FR-xxx`, `NFR-xxx`, `AC-xxx`, `TASK-xxx`, `ADR-xxx`). Agent-specific files (`AGENTS.md`, tool-local memory) are thin adapters, never the source of truth.

## Context

SPEC §§3.1, 21, 27: the same `.forge/` must be understandable by different agents. Each tool ships its own instruction/memory conventions that change over time.

## Alternatives

- Standardize on one tool's format (e.g. `AGENTS.md`-only or a proprietary memory dir).
- Structured YAML/JSON store with generated markdown views.

## Reason

- Markdown is the common denominator every coding agent already reads; no parser or server needed.
- Stable IDs survive rewrites and let tasks/decisions reference requirements unambiguously.
- Adapter pattern lets `AGENTS.md` point into Forge without forking context per tool; Forge never depends on proprietary formats.
- Humans can audit everything with any editor + git.

## Status

Accepted
