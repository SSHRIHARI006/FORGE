# ADR-002: Single Active Agent with File-Based Handoff for V1

## Decision

V1 uses one active coding agent at a time. Handoff state lives in `KICKOFF.md`, `state.md`, and `tasks.md`. No dedicated handoff file, no parallel multi-agent execution, no automatic orchestration in V1.

## Context

SPEC §§19–20: agents are workers, not owners. Sessions end (limits, tool switches: Freebuff → OpenCode → Antigravity). The next agent must recover from files + git alone.

## Alternatives

- Parallel agents with role assignment and merge protocol.
- Dedicated `HANDOFF.md` per session.
- Orchestrator assigning tasks to agents.

## Reason

- Sequential single-agent is the smallest mechanism that proves persistence across tools and sessions.
- Three files already cover the need (kickoff summary, mutable state, task ledger); a fourth handoff file would duplicate and drift.
- Parallel execution adds conflict-resolution and observability complexity with no V1 requirement driving it (deferred to V4 per SPEC §31).

## Status

Accepted
